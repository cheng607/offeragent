# OfferAgent 技术架构文档

> 版本：v1.0  
> 日期：2026-09-01  
> 说明：本文档描述 OfferAgent 的整体技术选型、模块划分、数据流与关键算法。

---

## 1. 设计目标

- **零构建依赖**：纯 HTML / CSS / JavaScript，无需 npm / webpack / vite。
- **移动端优先**：响应式布局，支持 iOS Safari 与微信内置浏览器。
- **离线可用**：所有资源本地加载，数据持久化到 `localStorage`。
- **可一键部署**：静态文件可直接部署到 GitHub Pages / Cloudflare Pages / 自有服务器。
- **可回溯可维护**：代码按职责拆分为独立模块，通过全局命名空间 `App` 组合。

---

## 2. 技术栈

| 层级 | 技术 |

## 4. 核心数据模型

### 4.1 题目（Question）

```js
{
  id: "fe-001",
  category: "frontend",
  difficulty: "medium",   // easy / medium / hard
  tags: ["JavaScript", "作用域"],
  question: "什么是闭包？",
  answer: "..."
}
```

### 4.2 学习卡片（Card）

每张题目对应一张学习卡片，记录记忆状态：

```js
{
  id: "fe-001",
  status: "learning",     // new / learning / mastered
  stage: 2,               // 当前间隔等级
  correctStreak: 3,       // 连续正确次数
  lapses: 1,              // 遗忘次数
  dueDate: 1234567890,    // 下次复习时间戳
  lastReview: 1234560000  // 上次复习时间戳
}
```

### 4.3 应用状态（State）

```js
{
  meta: {
    version: 1,
    createdAt: 1234567890,
    lastSync: 1234567890,
    dailyNewGoal: 5,
    dailyReviewGoal: 20
  },
  cards: { /* id -> Card */ },
  log: [
    { id, rating, ts, type } // 每次评分记录
  ],
  stats: {
    streak: { current, longest, lastDate },
    daily: { "2026-09-01": { learned: 3, reviewed: 5 } }
  }
}
```

## 5. 艾宾浩斯记忆调度算法

### 5.1 默认间隔序列

参考艾宾浩斯遗忘曲线与常见间隔重复算法，默认间隔为：

| 阶段 | 间隔（天） |
|------|-----------|
| 0    | 0（新题当天到期） |
| 1    | 1 |
| 2    | 2 |
| 3    | 4 |
| 4    | 7 |
| 5    | 15 |
| 6    | 30 |

### 5.2 评分映射

用户每次复习后给出 0-3 分：

| 评分 | 含义 | 行为 |
|------|------|------|
| 0（忘记）| 完全想不起来 | stage 归零，lapses +1，当天到期 |
| 1（模糊）| 有印象但不完整 | stage 降 1 级，间隔缩短 |
| 2（记得）| 能回忆起来 | stage +1，进入下一间隔 |
| 3（牢记）| 非常熟练 | stage +2，连续 5 次牢记直接掌握 |

### 5.3 掌握判定

满足以下任一条件即视为掌握（`mastered`）：

- 卡片 stage 达到最大间隔等级（默认 6）。
- 连续 `masterStreak` 次（默认 5 次）给出 3 分（牢记）。

掌握后卡片不再进入复习队列，但仍保留在题库中，可通过「重置进度」恢复。

### 5.4 每日队列生成

1. **复习队列**：筛选 `status !== mastered && dueDate <= 今天 23:59` 的卡片。
2. **新题队列**：按分类顺序挑选 `status === new` 的卡片，数量不超过每日新题目标。
3. **学习队列**：复习优先，新题次之，顺序可混合或分块展示。

## 6. 模块职责与数据流

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   bank.js   │────▶│  storage.js │◀────│ scheduler.js│
│   题库数据   │     │  状态持久化  │     │  记忆调度    │
└─────────────┘     └──────┬──────┘     └─────────────┘
                           │
                           ▼
                    ┌─────────────┐
                    │   app.js    │
                    │  UI 控制器  │
                    └──────┬──────┘
                           │
           ┌───────────────┼───────────────┐
           ▼               ▼               ▼
      ┌─────────┐    ┌─────────┐    ┌─────────┐
      │ stats.js│    │charts.js│    │ style.css│
      │ 统计计算 │    │ SVG 图表 │    │ 视觉样式 │
      └─────────┘    └─────────┘    └─────────┘
```

- **bank.js**：只读题库，提供按 ID、分类、标签查询的 API。
- **storage.js**：唯一的状态持久化入口，封装 `localStorage` 读写、版本迁移、导入导出。
- **scheduler.js**：纯函数式调度，输入卡片与评分，输出更新后的卡片状态。
- **stats.js**：基于当前状态计算各类统计指标，不修改状态。
- **charts.js**：将 stats.js 计算结果渲染为 SVG。
- **app.js**： orchestration 层，负责视图生命周期、事件绑定、把用户操作转化为 storage + scheduler 调用。

## 7. 移动端适配策略

- **Viewport**：`width=device-width, initial-scale=1.0, viewport-fit=cover`
- **安全区**：底部导航使用 `env(safe-area-inset-bottom)` 避让 iPhone 刘海/横条。
- **触控优化**：按钮最小点击区域 44×44px；禁用 `-webkit-tap-highlight-color`。
- **响应式容器**：`.app` 最大宽度 480px 并居中，小屏撑满，大屏如手机居中显示。
- **字体**：使用系统字体栈（PingFang SC / Microsoft YaHei），无需加载网络字体。
- **动画降级**：支持 `prefers-reduced-motion`，减少动效偏好下禁用翻转与过渡。

## 8. 部署方案

### 8.1 GitHub Pages

1. 将代码推送到 `cheng607/offeragent` 仓库。
2. 在仓库 Settings → Pages 中选择 Source 为 `main` 分支 `/ (root)`。
3. 访问 `https://cheng607.github.io/offeragent/` 即可使用。

### 8.2 微信内置浏览器

由于本项目是网页，可直接通过微信聊天或二维码分享链接，在微信内置浏览器打开。如需更原生的体验，可后续基于本代码封装为微信小程序或 PWA。

---

## 9. 可扩展点

- **题库扩展**：在 `js/bank.js` 中按 JSON 格式追加题目即可。
- **算法调参**：修改 `js/config.js` 中的 `STAGES`、`RATING_MAP`、`MASTER_STREAK`。
- **主题切换**：CSS Variables 集中在 `:root`，可扩展暗色模式。
- **后端同步**：可在 `storage.js` 中增加 `syncToCloud()` 钩子，将 `state` 同步到服务器。
- **微信小程序**：将 HTML/CSS/JS 迁移到小程序 WXML/WXSS/JS，复用核心逻辑。
